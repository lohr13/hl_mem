# v0.20.1 — Watchdog and Request Observability

发布日期：2026-08-02

## 概要

v0.20.1 是针对本地常驻服务可靠性的补丁版本。它修复 LLM 提取 schema 对非规范 `canonical_attribute` 过早拒绝的问题，将 `/healthz` 收敛为不访问数据库的异步存活探针，并增加 Windows watchdog 与 HTTP 请求生命周期日志，便于自动恢复和事故定位。

## 修复与增强

- `canonical_attribute` 的结构化输出约束由规范格式正则放宽为非空字符串；规范化仍由领域层负责，无法识别的值安全回退为 `custom.unknown`，不会再让提取 Job 因模型输出格式偏差直接失败。
- `/healthz` 不再打开 SQLite 连接或聚合数据库中的 LLM span，并改为 `async def`；组件、配置、向量检索、召回副作用与 monitoring 信息继续来自进程内快照。
- `scripts/hlmem_watchdog.sh` 可由 Windows 计划任务每两分钟运行。默认连续三次、每次五秒的探测失败后，脚本保存探测记录、端口/PID 树、进程资源、数据库文件元数据、日志尾部和可用的 `py-spy` 栈，再终止异常进程树并调用启动脚本。
- watchdog 使用跨次状态、60 秒重启冷却和带 owner 的原子目录锁；诊断、终止或启动失败会保留失败状态，供下一次计划任务继续处理。完整安装和验证步骤见 [Windows watchdog 运维指南](../watchdog.md)。
- FastAPI 新增请求生命周期 INFO 日志：`request_started` 和 `request_finished` 记录方法、路径、状态码及单调时钟耗时；可选 `X-Request-ID` 经字符过滤和长度限制后写入 start 事件，异常请求仍记录 500 finish 事件并继续抛出原异常。
- 生产启动脚本现通过专用 logging 配置为 `hl_mem` logger 启用 INFO 输出，确保请求生命周期日志实际写出，同时保持第三方库的日志级别不变。

## 升级与兼容性

- 包版本、项目元数据和 lockfile 统一升级到 `0.20.1`。
- 本版本没有新增或修改 SQL migration；最新 migration 仍为不可变的 `036_tokenized_fts_v2.sql`。
- REST 路由和 MCP 工具契约不变，因此 OpenAPI/MCP 快照无需更新。
- `/healthz` 保留版本、配置、组件和进程内指标，但不再返回需要数据库查询的 24 小时 `llm_stats` 聚合。依赖该字段的运维脚本应改用数据库只读审计或其他专用统计入口。

## 运维提示

watchdog 是面向当前 Windows 10 单机部署的外部恢复措施，不随 Python 服务自动注册。升级代码后需按运维指南显式创建计划任务，并在首次运行后确认 `var/watchdog.log` 出现成功探测记录。事故包可能包含进程命令行和日志片段，应限制目录权限并配置本机保留策略。
