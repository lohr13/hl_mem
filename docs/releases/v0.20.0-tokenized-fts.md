# v0.20.0 — Tokenized FTS v2

发布日期：2026-08-01

## 概要

本版本将 claims、events 和 claim topic tags 的生产检索从旧 FTS 索引直切到预分词 FTS v2。中文文本在写入前使用 jieba 分词，SQLite FTS5 使用 `unicode61` 索引稳定的空格分隔词项；dense 与 reranker 通道保持不变。

## 迁移内容

- 新增确定性 lexicalizer：NFKC 归一化、jieba 领域词典、stopwords、技术标识符整体词与分段词。
- migration 036 新增 `claims_fts_v2`、`events_fts_v2`、`claims_tags_fts_v2`，并为源行删除配置 orphan cleanup trigger。
- `ClaimRepository` 只从 `claims_fts_v2` / `claims_tags_fts_v2` 读取，并使用 `prepare_fts_query()` 构造安全 MATCH 查询。
- `EventRepository` 只从 `events_fts_v2` 读取，并使用同一 query lexicalizer。
- 新 claim/event 在源行与 v2 文档写入完成后统一提交；`commit=False` 时由调用方事务统一提交或回滚。
- `backfill_index_text()` 的 compare-and-set 更新成功后，在同一事务替换 `claims_fts_v2` 文档。
- 提供按 channel 原子重建的 `backfill_tokenized_fts` 工具。当前评测库完整性检查结果为 claims 1,376 行、events 11,941 行、tags 1,376 行，源表与 v2 rowid 集合一致。
- `Database` 在 migration 036 后校验三个 source/v2 rowid 集合；不完整时用单个 `BEGIN IMMEDIATE` 原子重建全部通道，成功前不向 repository 暴露连接。合法 JSON 但缺少字符串 `text` 的历史 event 会索引为空文档，不会中断升级。
- 旧 trigram/raw FTS 表暂时保留用于版本回滚，但生产查询不再调用 trigram fallback 或 legacy query sanitizer。

## 指标对比

30-case 数据集中的 q13、q16、q18 经数据库原文核对均无对应事实，已由错误的 answerable gold 修正为 no-answer。修正后共有 17 条有证据正例和 13 条 no-answer。

| 版本 / 口径 | 正例数 | Hit@1 | Hit@5 | MRR |
|---|---:|---:|---:|---:|
| v0.19.1 原始标签 | 20 | 0.6500 | 0.7500 | 0.6917 |
| v0.19.1 有证据子集 | 17 | 0.7647 | 0.8824 | 0.8137 |
| v0.20.0 tokenized FTS v2 + real dense/reranker | 17 | 0.8235 | 0.9412 | 0.8725 |

评测使用项目配置的 `text-embedding-v4` 与 `gte-rerank-v2`。纯 FTS 在这组语义改写问题上的 Hit@5 为 0.1765；该值用于诊断，不代表 hybrid 生产召回门禁。

## 已知问题

- q08“向量模型”仍依赖语义别名与 reranker 融合改进，未在本版本解决。
- 13 条 no-answer 查询仍会被 dense 通道补足候选，当前 no-answer precision 为 0；拒答阈值标定不属于本次 FTS 迁移。
- 绕过 repository 的原始 SQL UPDATE 无法运行 Python lexicalizer，且 rowid 完整性检查不能识别内容陈旧；可使用 `backfill_tokenized_fts` 重建。原始 SQL INSERT 造成的缺行会在下次启动时自动重建，源行 DELETE 已由 trigger 清理 v2。
- legacy FTS 表仍占用空间。计划在后续 migration 037、回滚窗口结束后删除。
- lexicalizer 首次加载 jieba 词典会增加冷启动时间；首次升级还会同步重建三个 v2 channel。热态 query 分词开销远低于远程 embedding/reranker 延迟。
