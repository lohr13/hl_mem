# v0.20.2 — Recall Quality and Cross-Platform Supervision

发布日期：2026-08-02

## 概要

v0.20.2 聚焦召回质量、诊断可解释性和常驻部署可靠性。query expansion 修复结构化输出契约并启用受控 `auto` 模式，slot hint 与 dense trace 补齐召回信号；28 条针对性评测为后续阈值决策提供配对 raw-score 证据。运维侧移除 Bash watchdog，以跨平台 healthcheck 和可选的 Windows 静默 supervisor 取代。

## 召回与诊断

- query expansion 的提示词现在明确要求输出 `queries` 键，避免模型返回语义正确但 schema 不匹配的对象。`Settings` 默认模式由 `off` 切换为 `auto`，短查询、指代查询或候选不足时按既有有界规则扩展。
- query expansion 可通过 `recall.query_expansion_model` 使用独立的 `glm-4.7`，避免占用主提取模型；单次请求超时为 5 秒，总预算为 6 秒，失败时仍只使用原始 query。
- slot hint 的 0.05 soft boost 同时匹配 `canonical_slot` 与兼容 `canonical_attribute`，并覆盖显存、VRAM、graphics card、处理器等高价值别名。
- 曾尝试以首轮 FTS 命中数和 dense top score 扩大 `low_recall` 触发面；本版本已回滚该升级，继续仅以可见候选数不足触发，避免在评测结论前增加额外 LLM 调用。
- dense repository 结果保留真实 cosine `_score`，SearchTrace 的 channel scores 可直接用于 raw-score 分布、问题定位和离线比较。

## Evaluation

- 新增 28 条针对性配对评测，覆盖 query expansion、slot hint 与低召回边界。
- `tests/eval/eval_runner.py` 支持 `pair_id`，并记录 dense cosine 与 reranker raw score；同一问题的 expansion on/off 结果可逐对比较，而不只依赖最终排序指标。
- 评测数据和运行结果继续留在仓库外；本次发布不引入敏感数据文件。

## 配置变化

- 仓库 `hl_mem.toml` 与 `config.example.toml` 将 `recall.default_limit` 从 20 调整为 5，以减少默认上下文噪声。
- 两份 TOML 将 `recall.relevance_reranker_floor` 从 0.4 下调到 0.15，并恢复 `recall.relevance_keep_top1 = true`，在扩大候选保留范围的同时保护 top-1。
- 上述两项是部署配置覆盖；`Settings` 的静态代码默认仍为 20 / 0.4。配置参考继续以 `Settings` 为 SSOT，并在 README 中明确这一区别。

## 监督与恢复

- 已删除 `scripts/hlmem_watchdog.sh`。`scripts/healthcheck.py` 只依赖标准库，统一探测 `/healthz` 并以退出码报告健康状态；systemd、Windows 服务管理器、Task Scheduler 或容器编排平台负责调用和告警。
- Windows 可选的 `scripts/hlmem_supervisor.py` 是单次执行部署助手：适合由 `pythonw.exe` 每两分钟静默调用，连续三次失败后才重启，并提供 60 秒冷却、跨次状态和防重叠锁。它会终止占用 8200 端口的进程树，再通过配置的启动脚本或项目虚拟环境无窗口拉起服务。
- 安装、验证和卸载命令见 [服务监督与健康检查](../watchdog.md)。使用 supervisor 前应确认仓库路径、虚拟环境和 8200 端口归属；运行日志与状态位于 `var/supervisor.log` 和 `var/supervisor.state`。

## 升级与兼容性

- 包版本、项目元数据和 lockfile 统一升级到 `0.20.2`。
- 本版本没有新增或修改 SQL migration；最新 migration 仍为不可变的 `036_tokenized_fts_v2.sql`。
- REST 路由、OpenAPI 契约和 MCP 工具契约不变。
- `query_expansion_mode` 的代码默认值已变为 `auto`，生产配置需要可用的 `LLM_API_KEY`；需要保持零扩展调用的部署应显式设置 `recall.query_expansion_mode = "off"`。
